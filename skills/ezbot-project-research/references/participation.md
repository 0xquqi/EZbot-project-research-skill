# 分步骤说明参与规则

针对用户选择的活动，逐步写清输入、动作、成本、产物和等待条件。依据来自当次读到的项目原文；本轮新例子见 source-catalog.json 与 case-studies.md。

- **直接铸造**：Bibi 为数量参数，Agent Punk Id 为一次一枚；同网站另一个系列可能不同，不能共用函数与限额。
- **证明或签名入口**：SeaDrop 将名单、签名、持有门槛分开。缺少官方提供的当前证明就说明阻塞点，不把任意旧 proof 填进去。
- **原生币与 ERC20**：本金、支付授权和 Gas 分开解释；不是所有支付都需要 approve。ERC-3009 签名转账也不等于普通 ERC20 allowance。
- **身份与数量**：BUILD 的共享身份次数与 AgentPunk 的钱包/卡片额度是目标规则，不是通用默认值。返利与铸造产物分别列出，不能把“返 LAB”写成“多铸一张”。
- **多阶段**：BUILD 提交后等待区块再揭示；ENS 文档还保留旧注册流程却明确入口停用。当前入口、等待条件、后续状态和是否过期必须逐项确认。
- **合成、质押、退款**：BUILD 合成会消耗输入卡，质押与直接转入不同。RefundEscrow 只在退款状态允许退款；找到该库不代表目标部署已开启退款。
- **随机与 PoW**：VRF 请求和回调不是同一时刻；0xBitcoin 的 mint 输入是挑战证明而不是购买数量。按各自实现判定完成和失败，不套普通数量铸造。

输出只读研究结论。用户另给已发生交易时，可用其链、交易与目标资产检查结果；当前归属可能因后续转移改变，应区分当时产物与现在余额。没有执行过就不写实操通过。
