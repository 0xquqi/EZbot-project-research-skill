# 参与机制与分阶段检查

| 机制 | 必须分开的事项 |
| --- | --- |
| 直接 mint / claim | 数量参数、产物、资格、当前供应、每号额度、报价总价 |
| 白名单 / 签名 | 申请、入选、证明/签名获取、有效期、链和钱包绑定、实际领取 |
| ERC20 支付 | decimals、本金、spender、所需授权额度、Gas、后续铸造 |
| 身份额度 | 钱包与身份的绑定、各自计数、免费与付费次数；换钱包未必重置 |
| 合成 / 激活 / 销毁 | 输入 tokenId/数量、不可逆消耗、权重、产物与后续领取 |
| 随机 / 预言机 | 请求费、回调、等待状态、产物、失败或退款；等待不等于失败 |
| PoW | 链、钱包、合约、锚定块/轮次、证明有效期、竞争导致失效 |
| 募资 / 退款 | 销售与退款窗口、触发者、接收者、扣款比例、旧部署与新部署 |
| 签名支付 / 中继 | 域、链、额度、nonce、有效期、逐订单结算；批次成功不证明每项 |
| 发射平台 | 是购买而非 NFT mint，平台版本、路由、转账限制、买卖分别可行性 |

报价要区分下一件单价与 `quote(wallet, quantity)` 的本次总价；免费额度横跨数量时逐档计算核对。输入付费数量、附赠数量、实际产物数量及占用供应可能不同。费用列出本金、授权 Gas、参与 Gas、协议/随机性费用和退款条件，未知项写未知。

## 交易结果的只读研究

用户给出已经发生的交易哈希时，可以用公开数据检查：正确链、from/to、回执状态、目标合约事件、ERC721 从零地址的 Transfer 与 ownerOf，或 ERC1155 TransferSingle/Batch 与余额。代币奖励检查目标 ERC20 的 Transfer/余额变化。后续转移或资产消耗也会改变当前归属，必要时区分交易发生时与当前状态。

回执成功不等于每个目标产物都到账；查不到回执不等于交易失败。无法读到链上结果时标未知，不重复发送。对结束或售罄的历史活动输出机制解释与查账方法，不给出仍可参加的教程。
