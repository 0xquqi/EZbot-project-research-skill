# 给用户的研究说明

先回答：这个活动做什么，目前找到哪条参与路径，哪些条件还不能确认。不要把空白字段堆成一份看似完整的交易方案。

按用户任务需要列出：

- 项目、活动名称、来源网址、目标链和地址用途。
- 每一步的官方入口或函数、需要的输入、产物、费用、等待条件；缺证的中间一步明确断开。
- 本金、支付币种/精度、附加费和 Gas；未知写未知，无具体钱包时不确认个人资格。
- 观察时点、链上区块（实际读到才填）、引用 URL 和证据范围。官网说法、源码规则与当前链读取不能互相冒充。
- 能确认的结论、当前阻塞和最小补充材料，例如明确链、找到当前 proof 入口或读取报价。

只在确认目标使用的全部关键条件后，才说当前可参与。页面可读不等于合约开放，接口异常不等于关闭。用户只让研究时，不调用签名、授权或交易工具。

报告无需采用历史归档的 JSON 字段。旧报告的格式与方法来源未完整确认，不能当本轮模板。
