# 从网页找到参与路径

## 从入口追踪到证据

记录输入 URL、重定向后的域名、页面标题、项目名称及访问时间。用官网与官方公告互相核对；第三方索引仅供发现。不要仅凭搜索排名、同名代币或页面按钮认定官方身份。

依次观察导航、活动卡片、Mint/Claim 按钮、文档和 FAQ。记录每一跳的 URL 和对应活动。网址含 `#home` 等片段可能是单页路由，静态 HTML 只有外壳时，用宿主浏览器渲染后查看 DOM、按钮状态和公开请求。需要连接钱包的页面，先研究公开文档和只读接口；连接、签名或发送不属于本 Skill 的动作。

若宿主允许检查公开前端资源，可读取当前页面实际加载的脚本、公开配置、ABI 和网络响应，找到链 ID、合约地址、函数与参数构造。把它们标为候选，随后与官方说明、区块浏览器和部署代码交叉核对。不要把脚本中的任意地址都当作铸造合约，也不要将测试网配置、旧版本、费用收款地址或身份注册表混入目标。

## 前端转化为研究说明

将前端行为写成一条可核实路径：

`官方活动页 → 当前链和部署 → 资格检查 → 报价/数量 → 授权（如需要）→ mint/claim → 等待或后续领取 → 产物核验`

对每一步记录：页面入口或函数、读取/签名/交易类别、输入与单位、前置条件、预期结果、来源和待核实项。只描述已经找到的路径；公开源码不足、后端签名缺失或验证码阻挡时停止在该边界。

标准前端不意味着标准合约。`mint(uint8)` 与 `mint(uint256)` 的选择器不同；按钮可能调用代理、路由、签名服务或多阶段流程。不要从按钮文字反推 ABI，也不要自动把任意网页转换为可执行交易。

## 读取失败

区分网站不可达、动态内容未渲染、身份要求、接口限流和项目明确关闭。重试应有界，保留错误来源与时间。可以用官方文档或公开源码补证，但标出没有实时确认的部分。不要用旧案例填补当前状态。
